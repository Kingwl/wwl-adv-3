# 测试

这里放长期测试策略和门禁说明。

## 测试分层

- 核心规则测试验证单个规则模块，例如卡牌、战斗和地牢移动。
- 核心流程测试验证玩家意图能串起来，例如探索、遭遇、战斗胜利、拾取物、出口解锁和过关请求。
- 场景 smoke test 只验证最小 UI 装配和关键可见状态，不作为长期玩法规格来源。

## 核心流程测试原则

- 不绑定 UI 节点、按钮文案、布局或具体场景实现。
- 不写死地图坐标、敌人编号或手牌顺序。
- 通过 `RunController` 的移动、自动遭遇、出牌、结束回合和出口请求等玩家命令驱动流程。
- 只断言稳定的玩法结果：遭遇会触发、战斗能胜利、敌人会清除、物品能收集、出口会解锁并请求过关。

## CI 门禁

CI 会先运行 scaffold 检查：

```bash
cd game
./tools/check-all.sh
```

随后安装项目固定的 Godot 版本，并运行所有 Godot headless 测试：

```bash
cd game
./tools/test-godot.sh
```
