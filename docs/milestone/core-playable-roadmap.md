# 核心可玩版本路线图

## 目标

构建 `wwl大冒险3` 的核心可玩循环：玩家在 2D 地牢地图中漫游，通过卡牌战斗攻击敌人，收集地图物品，从敌人掉落中获得经验并升级，最终跑通 2-3 个关卡。每个关卡目标为 10-15 处敌人遭遇。

原型可以参考 Vampire Crawlers 的手感，但不复制它的外观：节奏快的回合制卡牌战斗、费用升序 combo、地图上可见的目标、经验驱动的成长、宝箱带来的构筑爆点，以及后期滚雪球式的连锁协同。

参考信号：

- Steam 页面将 Vampire Crawlers 描述为带地图、等级成长、卡牌 combo、宝箱、宝石和地牢探索的回合制 roguelite deckbuilder。
- Xbox Wire 文章强调了第一人称地牢探索、地图上可见的敌人/物品/boss、有限 mana 回合、弃牌和抽牌洗回、升序 mana combo、经验升级以及局内/局外成长。

## 设计支柱

- 快速战术回合：每个战斗回合都应该能在几秒内读懂，同时奖励认真安排出牌顺序。
- 可见地图规划：敌人、拾取物、出口和关键奖励要足够可见，让玩家能主动选择路线。
- 小选择，大连锁：前期奖励保持简单，但组合起来要能在第 2 或第 3 关变得夸张。
- 规则确定性：相同 seed 和相同输入序列应产生相同的地图、奖励选项、敌人行动和 modifier 结算顺序。
- 场景轻逻辑：UI 只负责展示核心状态并发送指令，不拥有玩法规则。
- 原型重组合而非广度：少量能互相配合的敌人、卡牌和物品，优先于大量互不相关的效果。

## 产品形态

第一个完整原型应该像一局短 run，而不是菜单 demo。

- 玩家从第 1 关开始，携带一个固定 starter deck。
- 每关是生成或手写的 2D 网格，包含墙、地面、敌人、拾取物和出口或 boss 门。
- 敌人占据地图格子。触碰或攻击敌人会进入卡牌战斗。
- 战斗先复用现有核心规则：mana、手牌、抽牌/弃牌、护甲、敌人攻击、胜利、失败和 combo 缩放。
- 击败敌人掉落经验，也可以掉落简单物品或拾取物。
- 升级时提供 3 个卡牌或属性选择。
- 物品作为被动 modifier，改变战斗或地图生存。
- 清理关卡出口后进入下一关。
- 清理第 2 或第 3 关后结束原型 run。

## 核心循环

### Run 循环

1. 选择或直接开始默认英雄。
2. 根据 seed 生成第 1 关。
3. 探索地图，选择靠近哪些敌人和拾取物。
4. 接触敌人后进入卡牌战斗。
5. 获得经验、卡牌、升级和物品。
6. 找到或解锁出口。
7. 进入下一关，并保留当前 deck、生命、物品和等级。
8. 通关最终关卡即胜利；玩家死亡即失败。

### 探索循环

1. 查看附近地图格子和可见目标。
2. 在固定网格上一格一格移动。
3. 决定战斗、拾取物品、绕路拿宝藏，或直接前往出口。
4. 通过核心事件结果结算格子交互。
5. 场景根据更新后的地图和 run 状态同步显示。

### 战斗循环

1. 从敌人数据和当前 run 状态创建遭遇。
2. 抽手牌并恢复 mana。
3. 按费用不下降的顺序出牌以提高 combo 倍率。
4. 使用抽牌、加 mana、wild、护甲和攻击卡构建本回合。
5. 结束回合，若敌人存活则结算敌人行动。
6. 胜利后把奖励返回 run 状态，并清除地图上的敌人格子。

### 奖励循环

1. 击败敌人后获得 XP。
2. 如果达到等级阈值，根据 reward seed 生成 3 个选择。
3. 应用一个选择：加卡、升级卡、加属性、获得物品或给卡加 modifier。
4. 如果有宝箱或地图拾取物，则在战斗后或探索中结算。
5. 下一次地图行动前重新计算派生状态。

## 玩法系统

### 地牢地图

核心数据：

- 关卡 id、seed、宽高、tile 数组、玩家位置、出口位置和清关条件。
- Tile 类型：墙、地面、入口、出口、宝藏、治疗、祭坛、锻造、陷阱、敌人、精英、boss。
- 敌人和拾取物使用 occupant id，和视觉节点分离。
- 可选可见性状态：已见、当前可见、隐藏。

原型规则：

- 第 1 关可以先使用手写 fixture，加快落地。
- 第 2 和第 3 关也可以先做 fixture 变体，再补程序生成。
- 地图应暴露可见目标列表，方便 UI 渲染路线相关标记。
- 移动返回结果对象：已移动、被阻挡、拾取物已收集、遭遇已开始、请求离开关卡或无操作。
- 敌人格子在敌人被击败前阻挡正常移动。
- 出口默认锁定，在满足关卡清理条件后解锁。

未来规则：

- 基础路线规划好玩后，再加可选战争迷雾。
- 静态敌人路线可玩后，再考虑移动敌人。
- 陷阱用确定性 tile 事件表达，不使用场景计时器。

### 关卡结构

每一关都应该有清晰身份和简单内容预算。

| 关卡 | 敌人数 | 地图尺寸目标 | 主要压力 | 清关条件 |
| --- | ---: | --- | --- | --- |
| 1 | 10-12 | 12x8 到 14x10 | 学习路线和 combo 基础 | 击败小 boss 或 8 个敌人 |
| 2 | 12-15 | 14x10 到 18x12 | 在更密集地图里选择战斗 | 击败 boss 守卫并到达出口 |
| 3 | 12-15 | 16x12 到 20x14 | 用更强协同生存 | 击败 boss 后到达出口 |

关卡内容预算：

- 70-80% 普通敌人。
- 10-20% 精英或更难敌人。
- 第 2 关之后至少 1 个 boss 或出口守卫。
- 每关 3-5 个拾取物或特殊格子。
- 每关 1 个保底构筑奖励：宝箱、锻造、遗物或卡牌进化机会。

### 玩家 Run 状态

核心字段：

- 生命、最大生命、mana、最大 mana、等级、XP、下一级 XP 阈值。
- Deck 列表，抽牌/弃牌/手牌继续由 `CardDeck` 管理，并记录卡牌升级。
- 被动物品库存。
- 按卡牌实例 id 挂载的 modifier。
- 关卡序号、已击败敌人 id、已收集拾取物 id，以及 seed stream。

原型默认值：

- 生命：40。
- 最大 mana：3。
- 起始手牌数：5。
- Starter deck：Strike x3、Bolt x2、Guard x2、Focus x1。
- 第一次升级阈值：10 XP，之后每级增加 8-12 XP。

### 卡牌

卡牌类别：

- 攻击：直接伤害、溅射伤害、多段攻击、处决低血目标。
- 防御：护甲、反伤、护甲转伤害、护甲保留。
- 流动：抽牌、获得 mana、弃牌再抽、按费用检索。
- Wild：费用灵活，能维持或修复 combo 链。
- 成长：XP、幸运、金币、奖励品质、升级加速。
- 诅咒/风险：高收益但会卡手、自伤或重置 combo。

原型卡池：

- 第一个可玩 run 保持 12-18 张卡。
- 每关引入 3-5 张新的奖励卡。
- 至少 4 张卡服务 combo 构建，而不只是打伤害。
- 至少 3 张卡和地图或奖励经济交互。

升级模型：

- 卡牌升级使用数据驱动：card id 加 upgrade id。
- 第一版每张卡可以只有一个升级。
- 后续升级可以分叉成两条路径：降费或加强效果。

Modifier 槽位：

- 宝石或 modifier 挂到卡牌实例上。
- 第一批 modifier：费用 -1、加伤害、加护甲、加抽牌、保留、溅射、总是延续 combo、复制一次。
- 每张卡初始 0-1 个槽位；锻造或物品奖励之后可以增加槽位。

### Combo 和回合经济

当前已实现规则：

- 出牌费用大于或等于上一张牌时延续 combo。
- 更低费用会重置 combo。
- 倍率从 100 basis points 开始，每多 1 层连击增加 25。

计划新增：

- Wild 卡无视费用延续 combo，并可设置下一张卡的费用下限。
- Combo 阈值可以在 chain 3、5、8、13 时触发物品 hook。
- 加 mana 卡要有价值，但必须通过上限避免无限回合。
- 抽牌卡要足够强，让第 2 关开始出现长链。
- UI 要高亮能延续当前 combo 的卡。

保护规则：

- 单卡复制触发每次出牌最多一次。
- 被动触发链有最大深度或每个事件最大触发次数。
- Mana 和抽牌效果按确定顺序结算。

### 敌人

敌人职责：

- 群怪：低血低伤害，常见 XP 来源。
- 肉盾：血量较高，稳定输出，测试 deck 伤害缩放。
- 玻璃炮：低血高攻击，制造目标优先级。
- 护盾怪：开局有 block 或会加 block，测试时机和缩放。
- 分裂怪：死亡后生成或揭示第二个敌人。
- 吸取怪：攻击 mana、手牌数或 combo 状态。
- 精英：组合两种普通职责，掉落更好奖励。
- Boss：作为关卡门槛，有多回合行动模式。

原型敌人池：

| 敌人 | 职责 | 关卡 | 备注 |
| --- | --- | --- | --- |
| Slime | 群怪 | 1 | 低血，教学攻击 |
| Bat | 玻璃炮 | 1 | 低血，更高伤害 |
| Skeleton | 肉盾 | 1-2 | 中血，稳定伤害 |
| Shield Imp | 护盾怪 | 2 | 开局带 block |
| Mana Leech | 吸取怪 | 2-3 | 若未击杀，降低下回合 mana |
| Bone Captain | 精英 | 2 | 肉盾加护盾 |
| Stage Warden | Boss | 2-3 | 攻击和防御交替 |

敌人意图：

- 核心层应暴露下一次敌人行动，供 UI 展示。
- 第一版可以使用固定循环行动。
- 后续再按 seed 和状态选择行动。

### 经验和升级

XP 规则：

- 普通敌人掉 2-4 XP。
- 精英掉 6-8 XP。
- Boss 掉 10-15 XP，并给一个保底大额奖励。
- 地图上可以有 XP 宝石或拾取物，但只靠敌人 XP 也应足够升级，不要求完美路线。

升级选择：

- 添加一张卡。
- 升级一张卡。
- 增加最大生命并少量治疗。
- 增加最大 mana 或临时 mana。
- 获得或强化一个被动物品。
- 添加或替换一个卡牌 modifier。

奖励生成：

- 选择项从 reward seed stream 生成。
- 除非奖励池不足，否则避免三个奖励都属于同一类别。
- 尽量至少给一个立即提升战斗力的选项，以及一个偏成长的选项。

### 物品和被动

物品类型：

- 战斗属性：力量、护甲加成、最大 mana、抽牌、手牌上限。
- 触发器：出牌时、攻击时、获得 block 时、击败敌人时、达到 combo 阈值时、升级时、拾取时。
- 地图功能：揭示格子、拾取时治疗、按路线给额外 XP。
- 奖励功能：额外选项、升级折扣、更高 modifier 出现率。

原型物品示例：

- Training Gloves：攻击造成 +1 伤害。
- Old Shield：每场战斗第一张防御卡额外给 +2 block。
- Pocket Spark：每场战斗第一次达到 combo chain 3 时造成 3 点溅射伤害。
- Quick Tome：每场战斗第一回合额外抽 1 张。
- Mana Charm：每回合第一次打出 0 费卡时获得 +1 mana。
- Hunter Badge：精英额外掉 +2 XP。
- Snack Pouch：治疗拾取物额外恢复 +4 生命。
- Gem Lens：每关第一个宝箱包含一个卡牌 modifier 选项。

### 拾取物和特殊格子

地图拾取物：

- Food：恢复固定生命。
- XP Gem：在战斗外获得 XP。
- Gold：作为未来商店或局外成长的占位货币。
- Chest：选择卡牌、物品或 modifier。
- Forge：升级卡牌，或给卡牌增加 modifier 槽。
- Shrine：用生命换更强奖励。
- Key：解锁可选宝藏或出口变体。
- Trap/Hazard：损失生命、获得 XP，或触发伏击。

原型落地顺序：

1. Food。
2. Chest。
3. Forge。
4. Shrine。
5. Hazard。

### 构筑流派

第一个原型应支持几个清晰 deck：

- Combo 终结者：用低费卡铺垫，再打出一张高费重击。
- 长链：通过 wild 卡、抽牌和 mana 让回合持续运转。
- 护甲引擎：护甲转伤害或反击。
- XP 经济：前期战斗弱一点，但升级更快、奖励更多。
- 溅射清场：单体较弱，但多敌遭遇更强。

每个流派至少需要一个 starter hook、一个中期奖励，以及一个能让它有明显差异的物品或 modifier。

### UI 界面

最小可玩 UI：

- 地图网格：玩家、敌人、拾取物、出口和选中格子详情。
- 玩家面板：生命、等级、XP 条、mana、抽牌堆数量、弃牌堆数量。
- 战斗面板：敌人、敌人意图、玩家 block、手牌、combo chain 和结束回合按钮。
- 奖励弹窗：升级和宝箱选择。
- Run 总结：到达关卡、击败敌人数、等级、获得卡牌和收集物品。

重要反馈：

- 高亮能延续 combo 的卡。
- 显示经过 combo 倍率和 modifier 后的预计伤害。
- 显示卡牌不能打出的原因。
- 显示路线相关格子标记，不用大段教程文字解释。

## 首个完整原型的非目标

- 不做完整局外永久成长，只保留占位数据结构。
- 不做完整内容经济、卡牌稀有度调优或大型解锁树。
- 不强依赖程序化美术管线。
- 不做复杂 AI 寻路，除非基础敌人移动确实需要。
- 不做第一人称渲染；除非明确改方向，本项目保持 2D。
- 地图、战斗、XP 和物品奖励可玩前，不做商店经济。
- 不做大型角色池；先从一个英雄开始，并留下扩展 hook。

## 里程碑

### M0 当前基线

状态：基本完成。

范围：

- Godot 项目和启动场景已存在。
- 核心卡牌战斗规则在 `game/scripts/core/` 下。
- 带 seed 的抽牌和 combo 缩放已存在。
- Godot headless 规则测试已存在。
- CI 已运行 scaffold 检查。

退出标准：

- `cd game && ./tools/check-all.sh`
- `cd game && godot --headless --path . -s res://test/godot/test_card_combat_core.gd`

### M1 地牢地图核心

目的：让玩家能在确定性的 2D 地牢中漫游，且地图规则不依赖场景 UI。

范围：

- 在 `game/scripts/core/dungeon/` 下添加地图模型。
- 表达地图宽高、tile 类型、占位、玩家位置、出口、敌人和拾取物。
- 添加基于 seed 的确定性地图生成或 fixture 加载。
- 添加 `StageConfig` 内容预算：敌人数、拾取物数量、出口规则和特殊格子配额。
- 添加移动规则：墙、地图边界、敌人和可选出口锁会阻挡移动。
- 玩家进入或交互敌人格子时，返回遭遇触发数据。
- 添加 2-3 个初始关卡配置，每关目标 10-15 个敌人。
- 添加地图事件结果对象：移动、拾取、被阻挡、敌人交互和出口交互。
- 添加第 1 关 fixture 地图，使其能在程序生成前先被渲染。

测试：

- 相同 seed 创建相同地图。
- 玩家不能穿墙或越界。
- 玩家能在地面格子上移动。
- 敌人和物品位置稳定且可查询。
- 未满足清关条件时出口保持锁定。
- Fixture 敌人数符合关卡配置。
- 移动到拾取物返回确定性的拾取事件。

退出标准：

- 核心地牢测试能 headless 通过。
- 地牢规则内没有 Godot 场景依赖。
- 能用 debug print 或临时场景显示完整 fixture 地图。

### M2 可玩战斗场景

目的：把现有卡牌战斗核心接入最小可玩 UI。

范围：

- 创建 run 场景，包含地图面板、玩家状态、敌人状态、mana、手牌和结束回合控制。
- 卡牌按钮通过 `CombatState` 出牌。
- 场景读取核心状态并同步 label/button，不拥有战斗规则。
- 添加从地图敌人进入战斗、从战斗返回地图的流程。
- 击败敌人后清理地图上的敌人格子。
- 添加固定敌人行动模式的意图显示。
- 给每张可打出的牌添加 combo 预览。
- 给当前不能打出的牌添加禁用状态和原因。
- 添加最小 run controller，在探索、战斗和奖励模式之间切换。

测试：

- 核心非法出牌测试：错误手牌索引、mana 不足、目标无效、目标已死亡、空牌库抽牌。
- 场景 smoke test 能 headless 加载 run 场景。
- Run controller 能在不依赖场景私有状态的情况下开始并结束一场遭遇。
- Combo 预览和实际出牌结果一致。

退出标准：

- 本地玩家能开始 run，进入一场遭遇，出牌，胜利，然后回到地图。
- `check-all.sh` 包含核心 Godot 规则测试。
- UI 显示地图、手牌、mana、生命、block、combo chain 和敌人意图。

### M3 经验、升级和物品

目的：让连续战斗变成持续成长的构筑。

范围：

- 添加玩家 run 成长状态：经验、等级、下一级阈值、deck 变化和物品库存。
- 敌人被击败后奖励经验。
- 升级时暂停流程并提供 3 个选择。
- 选择可以加卡、升级卡、增加最大生命、增加最大 mana，或添加简单被动物品。
- 添加地图拾取物：治疗、金币占位、宝箱和卡牌奖励。
- 添加 6-10 个第一版物品，并使用确定性 modifier。
- 添加按关卡和奖励类型划分的奖励池。
- 添加卡牌 modifier 槽位，即使第一版只有少量 modifier。
- 添加第一批拾取格子结算：Food、Chest、Forge、Shrine。
- 添加通过明确事件输入/输出修改战斗的物品 hook。

测试：

- XP 阈值产生精确的升级事件。
- 升级选择对 seed 稳定。
- 应用奖励只改变 run 状态。
- 物品 modifier 通过明确核心 hook 影响战斗。
- 宝箱奖励不能重复收集。
- Modifier 只作用于所属卡牌实例。
- 被动 hook 按稳定顺序触发。

退出标准：

- 在一个关卡中击杀敌人至少能触发一次升级。
- 玩家能拾取物品，并感受到可见的战斗变化。
- 玩家能在 run 中升级或修改卡牌。

### M4 关卡循环

目的：做出带 2-3 个关卡的完整短 run。

范围：

- 添加关卡状态机：run 开始、关卡开始、探索、战斗、奖励、关卡完成、run 胜利、run 失败。
- 添加 2-3 个关卡配置，每关 10-15 个敌人遭遇。
- 添加清关条件：击败 boss、找到出口，或击败足够敌人。
- 添加基础敌人变化：低血群怪、阻挡者、高伤威胁和关卡 boss。
- 添加 run 总结 UI。
- 添加每关奖励预算，使第 2 和第 3 关有更强构筑压力。
- 添加关卡间 run 继承：生命、deck、物品、等级、XP。
- 如节奏需要，添加可选营地/休息格。
- 添加关卡介绍数据：敌人集合、地图主题和清关目标。

测试：

- 关卡完成会进入下一关。
- 最终关卡后触发 run 胜利。
- 玩家生命到 0 时触发 run 失败。
- 关卡敌人数符合配置预算。
- 战斗/奖励切换后，已击败敌人和已收集物品不会重新出现。
- 关卡继承保留 deck、物品、等级、XP 和生命。

退出标准：

- 一个完整 2 关 run 可以从开始玩到胜利或失败。
- 第 3 关配置可以在不改规则代码的情况下启用。
- 第 2 关通过敌人数值、敌人职责或地图路线压力，明显比第 1 关更难。

### M5 滚雪球机制

目的：加入类似 Vampire Crawlers 的构筑加速，让中后期变得爆炸。

范围：

- 添加 wild 或费用灵活卡，让它们能延续 combo。
- 添加卡牌 modifier 或宝石：降费、加抽牌、加 block、溅射伤害、出牌复制、按 combo 长度触发。
- 添加简单配方驱动的武器/卡牌进化规则。
- 添加被动连锁 hook：出牌时、击败敌人时、升级时、拾取时、达到 combo 阈值时。
- 添加简单平衡 telemetry 日志：关卡通过率、平均回合数、等级数。
- 添加至少 3 种能通关原型的构筑流派。
- 添加进化卡，使其替换或转换现有卡牌，而不是只追加更多卡。
- 为失控触发添加上限和日志，使破坏性构筑可见且可调试。
- 正确性稳定后，再添加可选快速战斗模式。

测试：

- Modifier 结算顺序确定。
- 延续 combo 的卡不能在没有明确上限时制造无限循环。
- 被动触发在每个事件上只按稳定顺序触发。
- 进化配方精确产出一个转换结果。
- 可以从 seeded smoke run 生成平衡 telemetry。

退出标准：

- 到第 2 关后期或第 3 关，一个好构筑能快速连锁多个效果，同时保持确定性和可测试。
- 游戏至少有一次令人满意的 combo turn：抽牌、mana、modifier 和被动可以明显级联。

## 节奏目标

- 第 1 关普通遭遇应持续 1-3 个玩家回合。
- 精英遭遇应持续 2-4 个玩家回合。
- Boss 遭遇应持续 4-7 个玩家回合。
- 第 1 关应产生 1-2 次升级。
- 第 2 关应产生 2-3 次升级。
- 第 3 关应产生 2-4 次升级，并至少出现一张进化或重度修改的卡。
- UI 可用后，完整 2 关 run 目标为 10-20 分钟。
- 快速战斗调优前，完整 3 关 run 目标为 20-35 分钟。

## 平衡旋钮

- 每关敌人生命和攻击。
- 敌人 XP 掉落。
- 等级阈值曲线。
- 每关宝箱和锻造数量。
- 奖励选项稀有度权重。
- 每层 combo 的倍率增量。
- 最大 mana 成长速度。
- 抽牌和 mana 卡的可获得性。
- 每个事件的触发上限。
- 治疗拾取物频率。

尽量把这些做成数据，避免调平衡时修改场景。

## 实现风险

- UI 可能意外成为 run 状态的事实来源。
- 被动物品 hook 如果没有明确事件结果，容易变得依赖结算顺序。
- 长 combo 支持可能产生无限抽牌或无限 mana 循环。
- 奖励类型太多会让第一版原型难以平衡。
- 每关 10-15 个敌人的地图如果没有路线选择、宝藏压力或敌人变化，会显得重复。
- 固定 fixture 更快，但边界要为后续程序生成保留空间。

缓解方式：

- 为地图、战斗、奖励和 run 切换添加事件结果对象。
- 尽量让被动 hook 保持纯粹：输入事件加状态，输出 delta。
- 在加入 wild combo 前，先添加触发上限和确定性顺序。
- 从 12-18 张卡和 6-10 个物品开始。
- 第 1 关使用手写 fixture，第 2/3 关先使用 fixture 变体，再做生成器。

## 架构规则

- 玩法规则放在 `game/scripts/core/`。
- Godot 场景只负责节点、输入、资源和状态同步。
- 随机性必须接收显式 seed，并在测试中保持确定性。
- 对 tick 或顺序敏感的系统要暴露稳定事件结果，便于测试。
- 奖励和物品效果优先做成数据定义，再写特例场景代码。
